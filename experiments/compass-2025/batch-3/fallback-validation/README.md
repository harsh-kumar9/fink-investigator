# Checking the local image crop

The 2018 July 16 public science-image cutout returned HTTP 503. Its underlying ZTF red quadrant was accessible. We requested bytes 0–65535 and received HTTP 200 with the complete 37,872,000-byte original. The April 24, 2025 green original behaved the same way, and its separately retrieved IRSA cutout provided a reference. Both full-file SHA-256 hashes, the selected byte ranges, cropped-file hashes and source URLs are recorded. [Verification measurements](results.json) · [IRSA image cutout interface](https://irsa.ipac.caltech.edu/ibe/cutouts.html)

The local crop from the April original is 164×164 pixels. All 26,896 pixel values and sky coordinates agree with the separately retrieved IRSA stamp, including the outermost pixels. The 2018 crop is also 164×164. Its lower-left pixel has zero-based coordinates (2542, 2398) on the original. The validator produced identical crop bytes from complete originals and from their preserved header and row sections. The section transfers in the verifier simulate a server honoring HTTP Range; the live server returned the complete originals in these two tests. [Recovery implementation](../image_fetch.py)

From the repository root, `python3 experiments/compass-2025/batch-3/fallback-validation/verify.py` repeats the two crops offline using NumPy and Astropy. Each fixture contains the exact first 65,536 bytes and a contiguous strip of original pixels covering the crop. The third input is the independent April service stamp. With the three complete files, the optional `--capture JULY_2018_FULL APRIL_2025_FULL APRIL_SERVICE_CUT` reconstructs the fixtures and checks the full and sectioned reads before recording their hashes.

After an IBE cutout failure, call `from_original(row, position)` with the same inventory row and sky center. It returns the cropped FITS bytes and the original-image transfer receipt. It reads the first FITS header, checks the filter and detector against the inventory, computes the bounds with the science WCS and preserves that WCS by translating its reference pixel. The default aggregate transfer cap per original is 40,000,000 bytes. A server honoring Range sends the header and the contiguous data strip. A server ignoring Range can send one complete uncompressed quadrant within the same cap. The current implementation supports unscaled, two-dimensional, single-precision ZTF science images.

## Two cases where another cutout URL worked

The standard encoded URL with `gzip=false` and the underlying original returned HTTP 503 for the red image on May 21 and the green image on May 25, 2025. A literal coordinate pair and the service's default gzip setting returned the red stamp. The green stamp required an explicit `gzip=true` with the same coordinates. The alternate helper checked the exposure ID, detector, filter, footprint and FITS dimensions. Both responses were gzip compressed 164×164 original-pixel stamps. The tests also recorded the unsuccessful paths. [Exact URLs, statuses, original and compressed SHA-256 values, and scientific-image aperture checks](may_service_checks.json) · [Documented IBE cutout syntax](https://irsa.ipac.caltech.edu/ibe/cutouts.html)

The downloads contained 95,534 bytes (May 21) and 98,654 bytes (May 25). The local measurements on the recovered stamps yielded signed fluxes with S/N below 5 on both dates. The server's response to a particular form of the request can change. The stored results refer to the exposures and requests tested here.
